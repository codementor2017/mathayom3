🎨 Lesson 3 — Designing the User Interface

⏱️ 100 minutes 📘 Indicator 1 🗓️ Semester 1 · Midterm 🎓 Grade 9

🧭 Lesson Opener

"Have you ever opened an app and instantly felt lost? You didn't know where to tap, or which button to press. It felt frustrating, right?"

That frustration is the result of bad user interface design. A good interface guides you gently toward your goal — like a well-marked trail through a forest. In this lesson, you will learn what a user interface is, the five principles behind good UI design, and how to sketch a clear screen for your own app.

🎯 What You Will Learn

By the end of this lesson, you will be able to:

  • Explain what a user interface (UI) is and why it matters.

  • Tell the difference between UI and UX.

📖 1. What Is a User Interface?

The user interface (UI) is everything a person sees and touches when they use an app. It includes the buttons, colors, text, images, sliders, icons, and the layout of the screen. In other words, the UI is the "face" of your app.

The user experience (UX) is different — it is how the user feels while using the app. A good UX feels smooth, fast, and satisfying. A bad UX feels confusing, slow, and stressful.

Key idea: The UI is what the user sees. The UX is what the user feels. You can't have good UX without good UI.

Imagine a phone with a beautiful screen but buttons that don't respond. The UI looks fine — but the UX is terrible. Now imagine a phone with a plain screen but everything works instantly. The UI is simple, but the UX is excellent. Great apps aim for both.

📖 2. The Five UI Design Principles

Professional designers follow five principles to make interfaces clear and pleasant.

1) Simplicity

Remove anything unnecessary. One screen should have one purpose. Too many buttons, colors, or messages overwhelm the user. A simple screen lets the user focus on what matters.

2) Consistency

Use the same colors, fonts, and button styles throughout the app. If the "Save" button is green on one screen, it should be green on every screen. Consistency helps users learn the app quickly.

3) Feedback

Always tell the user what happened. If they tap "Save," show a message like "Saved!" If they enter a wrong value, show a red warning. Without feedback, users feel unsure.

4) Accessibility

Make the app usable for everyone — including people with poor eyesight or color blindness. Use large fonts, clear contrast between text and background, and don't rely on color alone to convey meaning.

5) Hierarchy

Put the most important information first. The title goes at the top, the main action button stands out, and secondary options are smaller. Hierarchy guides the eye.

Example — A good BMI Calculator UI:
  • Title: "BMI Calculator" (clear, at the top).
  • Two labeled inputs: "Weight (kg)" and "Height (m)".
  • One big "Calculate" button (obvious).
  • Output: "Your BMI is 22.0 — Normal" (with category).
  • Reset button (secondary, smaller).

📖 3. Sketching a UI

Before you code a screen, you should sketch it. Designers sketch on paper because it is fast, cheap, and easy to change. A sketch (also called a wireframe) shows the layout — where the buttons, inputs, and outputs go.

A good sketch labels every element and shows the user flow — what happens after each tap.

Steps to sketch a UI:

  1. Draw a rectangle for the phone screen.
  2. Place the title at the top.
  3. Place the inputs below the title.
  4. Place the main action button (the biggest one) in the middle.
  5. Place the output below the button.
  6. Add secondary buttons (like "Reset") at the bottom.
  7. Label each element clearly.
Tip: Use a pencil, not a pen. You will change your sketch many times before you are happy with it. That is normal — even professional designers revise.

Activity 3 — Sketch Your Own Screen 10 min

Take a piece of paper. Sketch the main screen of the app idea you planned in Lesson 2.

Include:

  • A title at the top.
  • All inputs the user needs to enter.
  • One clear action button.
  • An output area.
  • Any secondary buttons (like Reset, Help).

Label every element with its purpose. When done, keep the sketch — you will refine it in the hands-on task.

🔍 Case Study — Why Google's Search Page Is a Design Masterpiece

The Google search page has barely changed in over twenty years. Why? Because it already follows every UI design principle perfectly.

  • Simplicity: just one input box and one button. Nothing else.
  • Consistency: the colors, logo, and layout are the same on every device.
  • Feedback: when you type, suggestions appear instantly. When you press Enter, results load.
  • Accessibility: large fonts, high contrast, works with screen readers.
  • Hierarchy: the search box is the most prominent element — nothing competes with it.

Now compare this with a badly designed site cluttered with ads, pop-ups, and flashing banners. Which one do you want to use again? Good design is not about looking fancy — it is about respecting the user's attention.

Reflect: Think of an app you use that follows these principles. What does it do well? Now think of one that does not. What would you change?

🛠️ Hands-On Task — Design Your App's UI

Using the sketch you started in Activity 3, create a clean final version on a new sheet of paper. Follow these rules:

  1. Use at least three colors (a main color, an accent, a background).
  2. Label every element with its purpose.
  3. Show the user flow with small arrows: what happens when the main button is tapped?
  4. Make sure the font size is easy to read from a distance.
  5. Check your design against the five UI principles — does it satisfy each one?

When you finish, display your sketch on your desk. In the last few minutes, walk around the room and look at three other designs. Leave one sticky note of positive feedback on each.

🔑 Key Takeaways

  • The UI is what the user sees; the UX is how they feel.
  • Five principles guide UI design: simplicity, consistency, feedback, accessibility, hierarchy.
  • Sketching on paper is the fastest way to design and improve a screen.
  • A well-designed UI guides the user gently toward their goal.
